CHAPTER 22 / 28 · VALIDATION

时序交叉验证

特征、模型、自动工具都准备好了，但“你凭什么相信模型能预测未来？”这个问题的答案只有一个：验证。这一章讲清为什么随机划分会在时序上虚高，以及怎样搭一套不会自欺的评估流程。

机制图解 · 原生数学排版 · 可复现模拟 · 防泄露

普通的机器学习课上，交叉验证是把数据随机切成 K 份轮流做验证。但时间序列是有序的：相邻观测高度相关，今天和昨天的值几乎一样。一旦随机打乱，“验证样本的邻居”就大量出现在训练集里，模型不是在预测未来，而是在回忆临近的过去。

这一章的每一节，都在回答同一个问题：怎样让验证流程和上线后的真实处境一致。

01 · 为什么不能随机 shuffle

下面是一个刻意构造的演示（不是真实案例）：如果有人用默认的 K-Fold 随机划分去评估一条自相关很强的序列，得到的分数会高得不真实。原因很直接：随机划分下，测试样本的前后邻居往往躺在训练集里，模型只要“找最近的历史”就能猜得很准。

把同一套流程换成训练全在测试之前的时间划分，分数会明显回落。回落后的数字才是“外推能力”的估计。第 20 章的 1-近邻实验已经展示了这一点（随机划分 R²≈0.89，时间划分 R²≈0.63），本章不再重复数字。

结论：时序评估永远不能随机 shuffle，训练集必须全部在测试集之前。

02 · 两种时序验证策略

扩展窗口（expanding）：训练集从起点开始不断变长，测试集是紧随其后、长度固定的一段。所有 fold 的测试长度相同；后期 fold 训练数据更多，计算也更慢。

滚动窗口（rolling / sliding）：训练集只保留最近一段固定长度的历史，随时间整体右移，测试集紧跟在训练窗口之后。每个 fold 的训练量恒定。

特性扩展窗口滚动窗口
训练数据量逐 fold 递增固定不变
计算成本后期 fold 变慢基本恒定
适合场景历史都有信息、样本量小分布随时间漂移、只需近期模式
对概念漂移的适应较弱（早期数据会拖累）较强（只关注近期）

选择哪一种，取决于你对“历史是否仍然有用”的判断，而这本身应该用数据回答：两种都跑一遍，看哪个在外推段更稳。

03 · 步长与 fold 数

步长（stride / step）是每个 fold 向前推进多少期。它不应小于预测步长 h，否则相邻 fold 的测试段会重叠，多次得分高度相关，你算出的“平均”其实只代表一小段时间。

步长过小则 fold 间重叠、信息重复；步长过大则 fold 数太少、得分方差大，调参会不知不觉过拟合验证段。一个稳妥的经验：让测试段不重叠，fold 数保持在 5–10 之间。

汇总时不能只看平均，还要看分布。时序评估常用各 fold 误差的平均：

E‾=1K∑k=1KEk
E_k 是第 k 个 fold 的误差（MAE/MASE 等）；还应同时报告 E_k 的极差或标准差，防止“平均好看、某段崩盘”。

04 · Purging 与 Embargo：防泄露的最后一道防线

即使按时间划分，当特征包含滞后项时仍可能泄露：测试段第一个样本的特征用到紧贴它的过去，而这些过去恰好在训练段末尾，两边“挨着”。两个来自金融机器学习（López de Prado）的工具可以处理这种情况：

  • Purging（剔除）：若某个训练样本的标签窗口或特征窗口与测试期重叠，就把该训练样本从训练集中删掉。
  • Embargo（隔离带）：在训练段与测试段之间留出一段禁止使用的间隔，使两者不借用近邻。
经验规则：最大滞后是 lag_28，就至少留 28 期的 embargo。这个细节在滞后很长、序列很平滑时足以决定结论真假。

05 · 时序集成：Blending 与 Stacking

在正确验证的前提下，集成多个模型往往能小幅提升稳定性。两种常见做法：

  • Blending（加权平均）：在验证段上根据各模型的误差确定固定权重（如误差倒数归一化），再线性组合。简单、稳定、不易过拟合。
  • Stacking（堆叠）：用一个元模型学习如何组合各基础模型的预测。更灵活，但元模型的训练必须严格使用时序交叉验证，否则元模型本身会泄露。

两者对“基础模型预测”的生成方式很敏感：基础模型的 out-of-fold 预测必须来自看不到对应测试段的模型。把这点做对，比换上更花哨的元模型更关键。

06 · 一个可复用的对比框架

把以上内容固定成一个流程，每次评估新模型都复用同一个函数，就不会“不小心”用了随机划分或让特征泄露。一个严谨的框架至少包含：

  1. 统一的时序交叉验证（扩展或滚动，测试段不重叠，fold 数 5–10）；
  2. 每个 fold 内重新做特征工程与预处理（scaler、插补、滚动特征都不能跨越划分边界）；
  3. 至少三个候选：简单基线（naive / 季节 naive）、统计模型、ML 模型；
  4. 必要时加 purging 与 embargo；
  5. 报告每个 fold 的分数与分布，而不只是平均值；
  6. 最后留出一段完全未参与任何选择的数据做终验。
基线的意义：如果花哨的模型没有显著超过 seasonal-naive 基线，就先用基线。很多“未上线模型”的失败，不是因为模型不够复杂，而是因为从未和一个诚实的基线对比过。

07 · Python 实验：扩展窗口交叉验证

下面用 numpy 对一个合成序列做扩展窗口交叉验证，基线模型是 naive 预测（用训练段最后一个值预测整个测试段）。重点是观察各 fold 的分数分布，而不只是平均分。只依赖 numpy。

import numpy as np
rng = np.random.default_rng(2200)
n = 200
t = np.arange(n)
y = 0.3 * t + 2 * np.sin(2 * np.pi * t / 7) + rng.standard_normal(n)

def expanding_cv(y, n_splits=5, test_size=14):
    scores = []
    start = len(y) - n_splits * test_size
    for k in range(n_splits):
        tr_end = start + k * test_size
        pred = np.full(test_size, y[tr_end - 1])       # naive：用训练末尾值
        scores.append(np.mean(np.abs(y[tr_end:tr_end + test_size] - pred)))
    return np.array(scores)

s = expanding_cv(y)
print("各 fold MAE:", np.round(s, 3))                # ≈ [3.23 2.15 2.65 2.54 2.05]
print("平均", round(s.mean(), 3), "标准差", round(s.std(), 3))  # ≈ 2.524 / 0.418
assert len(s) == 5

预期结果：各 fold 的 MAE 在 2.05–3.23 之间波动，平均约 2.52、标准差约 0.42。只看平均值会掩盖“某个时段明显更差”这件事。这是合成数据上的机制演示，不代表任何真实序列的误差水平；真实项目应换用与业务对齐的误差指标（如 MASE）。

08 · 小结

时序验证的全部要点可以归结为一句话：让验证流程尽可能接近上线时的真实处境。训练不晩于测试、测试段不重叠、预处理不跨边界、必要时加隔离带、报告分布而非单点。

交付任何预测结论前请先回答：划分是按时间做的吗？步长不小于预测步长吗？每个 fold 内是否重新拟合了 scaler 与特征？最大滞后对应的 embargo 留了吗？除了均值，各 fold 的极差是多少？最后一段终验数据真的没参与选择吗？
