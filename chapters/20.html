CHAPTER 20 / 28 · TREE MODELS

树模型与时序预测

上一章把序列变成了特征表格。这一章回答“该用什么模型”：梯度提升树为什么擅长非线性与交互，又为什么不能外推趋势；以及特征重要性和验证策略里最容易踩的坑。

机制图解 · 原生数学排版 · 可复现模拟 · 泄露诊断

如果去时序预测的竞赛或工业方案里看一眼，梯度提升树（XGBoost、LightGBM、CatBoost）几乎总在获奖名单里。它在很多实用场景里接替了经典 ARIMA，成为表格型预测的主力。原因不是“树模型更高级”，而是它恰好匹配了现实数据的几个性质。

但树模型不是万能的，尤其在时间序列上有一处结构性弱点——无法外推。理解它的能力边界，比记住一套调参口诀重要得多。

01 · 为什么用树模型

把序列变成特征表格后，剩下的就是回归问题。线性回归假设目标与特征近似线性可加；而真实数据往往不是这样。树模型在这几个方面有明显优势：

  • 非线性：促销的边际效益递减、温度对用电量的 U 型影响、广告投入的饱和效应，树用阈值分裂就能分段逼近，无需手工构造多项式或交互项。
  • 特征交互：销量可能取决于“温度 × 是否周末 × 是否节假日”。线性模型需显式相乘；树的分裂路径天然表达条件依赖。
  • 对异常值相对稳健：分裂基于排序阈值，单个极端值对结构影响有限，而线性模型和神经网络会被它明显带偏。但这不是免疫——多个异常值仍会改变分裂点。
  • 缺失值友好：XGBoost、LightGBM 在训练时会为缺失值学习默认分裂方向，无需先填充；但上一章的泄露与可得性原则仍然适用。

这些优势有前提：树模型需要足够多的样本才能可靠分裂，并且它学到的是一张分段的常数映射。这一点直接导致了下一节要讲的外推缺陷。

02 · 梯度提升机制

梯度提升树不是“一棵大树”，而是许多浅树相加。每一轮新增一棵树去拟合当前模型的残差，并用学习率 ν（步长）缩小它的贡献，形成逐步逼近。

Fm(x)=Fm−1(x)+νhm(x),hm≈arg minh∈𝒯∑iℓ(yi,Fm−1(xi)+h(xi))
ν ∈ (0,1] 是学习率：越小则每棵树贡献越少、需要的树越多，但通常更稳健。对平方损失，hm 就是在拟合负梯度（即残差）；对其他损失则是拟合广义残差。

这解释了两个常见现象：学习率越小、树越多，模型越平滑也更慢；而树太深会让单棵树记住噪声，泛化变差。所谓“调参”，本质上是在加性拟合的容量与稳定性之间取平衡。

03 · 三大框架的差异

XGBoost、LightGBM、CatBoost 都是梯度提升树，但工程实现不同，适合的场景也不同。下表汇总的是各自官方文档与论文都明确声明的实现特征，而非效果排名：

特性XGBoostLightGBMCatBoost
默认生长方式按层生长（level-wise）按叶生长（leaf-wise）对称（oblivious）树
类别特征需手动编码需手动编码（有 categorical 支持）原生目标统计编码
缺失值原生默认方向原生默认方向原生处理
大数据训练速度中等通常较快中等

选择上的稳妥建议是：样本量很大、追求速度时优先试 LightGBM；类别特征多且不想手工编码时优先试 CatBoost；需要成熟生态和丰富接口时用 XGBoost。但“哪个好”最终应由你自己数据上的时序交叉验证决定，而不是别人的榜单。三者对超参数都敏感，默认参数不一定适合时序数据。

04 · 树模型不能外推趋势

这是树模型在时序上最重要的结构性限制：树的预测是分段常数，永远落在训练数据的取值范围内。如果把“趋势”直接作为特征或目标，测试期的取值超出训练范围时，树只能输出边界值，无法延续上升或下降。

实践中有两种应对：一是把趋势显式建模（如先差分、去趋势，或用确定性的时间/傅里叶特征让模型学到趋势形状——但傅里叶外推只在周期内可信）；二是把树模型的残差交给一个能外推的组件（线性回归、ARIMA）。直接把“时间序号 t”当作特征能让树在训练区间内拟合趋势，但一旦 t 超出训练范围，同样会撞到边界值。

m=5 时，训练区间内是 5 段阶梯；超过 x=1 后预测停在最后一片叶子，不再上升。

教学示意：假设真实趋势为 y=2+3x（训练区间 x∈[0,1]），树用等宽分箱的叶子均值近似，越界后沿用最后一片叶子的取值；柱高按最大预测值归一，横轴为 0 到 1.6 的 12 个等距查询点。

05 · 特征重要性的陷阱

树模型自带特征重要性，但它容易被误读。XGBoost 默认提供的三种指标含义不同：

  • weight：被用作分裂的次数，容易被取值多（高基数）的特征主导；
  • gain：分裂带来的平均信息增益，常用但偏向靠近树根、相关性高的特征；
  • cover：分裂覆盖的样本数，受特征取值分布影响大。

它们都描述“模型内部如何使用特征”，不等于因果效应，也不能用来断言“某个特征驱动了目标”。更可靠的做法是用置换重要性（permutation importance）评估打乱一个特征后模型误差的上升，或用 SHAP 值看单个预测的归因。两者都应在按时间划分的验证集上计算，否则同样会被泄露污染。

常见误用：把 gain 排名第一的滞后特征解读为“存在动量效应”。高相关特征常被优先选作根节点分裂，gain 自然偏高；相关≠因果，且高的 gain 也可能来自泄露。结论必须回到时序验证和可解释的机制上。

06 · 时序验证与 look-ahead bias

树模型不会自己尊重时间顺序，它把每一行当作独立样本。如果直接用 train_test_split 的默认随机划分，测试行的时间窗口就与训练行交织在一起。对于高度自相关的序列，“未来行”的相似邻居很可能就在训练集里，模型不是在预测未来，而是在回忆临近的过去。这就是 look-ahead bias（前视偏差）。

本节只给出结论方向，具体时序交叉验证的方法与代码放在第 22 章。这里的核心原则是：训练数据的时间必须早于验证数据，并在两者之间留出至少 h 步的间隔，避免重叠窗口跨界。

看到离谱的高分先怀疑泄露：时序任务上 0.99 的 R² 或 99% 的方向准确度通常是前视偏差、目标泄露或随机划分造成的，而不是模型强大。排掉泄露后再评估。

07 · 调参与实践建议

树模型的超参数对时序数据很敏感，以下是官方文档中常见参数与它们在时序场景下的调整方向：

参数作用时序场景取向
learning_rate每棵树的步长取小（0.01–0.1）+ 更多轮，更稳健
max_depth / num_leaves单树容量特征少时调浅（3–5），特征多可加深
subsample行采样比例时序样本相关，不宜过小
min_child_weight叶节点最小权重调高可抑制对噪声的过拟合
lambda / alphaL2 / L1 正则时序噪声大，正则往往比表格任务更重要

两点必须强调：第一，验证策略必须是时序的，用随机 K-Fold 调出来的参数会在上线时失效；第二，特征工程对结果的影响通常大于模型选择，与其反复调参，不如先把滞后、滚动、日历与傅里叶特征做对、把泄露排干净。

08 · Python 实验：随机划分如何制造假高分

下面用 numpy 造一条随机游走序列，特征用上一期值 yt−1，目标为当期 yt，预测器用最简单的 1-近邻（在特征空间里找最接近的训练点）。对比随机划分与时间划分两种验证方式。只依赖 numpy。

import numpy as np
rng = np.random.default_rng(2000)
n = 400
steps = rng.standard_normal(n)
y = np.cumsum(steps * 0.5)             # 随机游走：相邻值高度相似
x, tgt = y[:-1], y[1:]                 # 特征 y_{t-1}，目标 y_t

def r2(a, b):
    return 1 - ((a - b) ** 2).sum() / ((a - a.mean()) ** 2).sum()

def knn(tr, te):
    pred = np.array([tgt[tr[np.argmin(np.abs(x[tr] - x[i]))]] for i in te])
    return r2(tgt[te], pred)

idx = rng.permutation(len(x)); cut = int(len(x) * 0.8)
print("random-split R2 =", round(knn(idx[:cut], idx[cut:]), 4))   # ≈ 0.8938
split = int(len(x) * 0.8)
print("time-split   R2 =", round(knn(np.arange(split), np.arange(split, len(x))), 4))

预期结果：随机划分得到的 R² 约为 0.89，而按时间划分只有约 0.63。差距不是模型变强，而是随机划分让测试点的“时间邻居”出现在训练集里。这是合成数据上的机制验证，不代表任何真实序列的可预测水平。

09 · 小结

树模型把上一章的特征表格变成一个强大的非线性回归器：加性拟合并行处理非线性与交互，对异常值相对稳健。但它的分段常数本质意味着不能外推趋势，特征重要性和随机划分又是两个最容易让人得出错误结论的地方。

使用树模型前请先回答：验证是按时间划分并留了间隔吗？特征里有没有同期或未来信息？目标需要外推趋势吗（若是，树的输出会撞到边界）？得出的重要性结论经过置换或 SHAP 交叉验证了吗？
