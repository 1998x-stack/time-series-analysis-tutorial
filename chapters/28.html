CHAPTER 28 / 28 · CAPSTONE PROJECT

综合实战项目：一条端到端的预测流水线

前 27 章逐个拆解了工具。这一章把它们重新组装起来，走一遍从原始数据到上线监控的完整路径，并说清哪些环节最容易出错。

机制图解 · 原生数学排版 · 可复现模拟 · 结论边界

前 27 章是拆开学：平稳性、ARIMA、树模型、神经网络、验证与部署。这一章把它们装回一条完整的流水线，以“预测未来 14 天日销量”为例——库存调拨、营销预算、人员排班都需要它。周期清晰、特征多样、容错空间有限，很适合当作综合练习。

先交代一个前提：下面涉及的数值只是教学示意。要在真实项目里复现结论，请替换成你自己的数据与业务口径，并用第 22 章的时序验证重新比较。本章的目标是流程与判断力，不是某个固定排行榜。

01 · 项目全景

整条流水线分 8 个阶段，前后有依赖，不能随意打乱：

02 · 数据清洗：促销、缺失与节假日

拿到数据后的第一步永远是清洗。电商日销量常见的几个坑：

  • 促销日尖峰：大促当天的销量可能是平日的数十倍。这些是真实值，不能当异常删掉；正确做法是把它标成一个特征（是否促销、促销力度），让模型知道峰值有因。
  • 缺失：系统故障可能造成断记。短缺口（1–2 天）可用线性插值；长缺口更宜用季节性均值，并同时标记“该段为插值”。
  • 节假日效应：春节、国庆等周期漂移的节日，需要用日历作为外部特征。
# 数据清洗示意图：插值 + 事件标记
import pandas as pd

df = pd.read_csv("daily_sales.csv", parse_dates=["date"]).set_index("date").sort_index()
df["sales"] = df["sales"].interpolate(method="linear", limit=2)   # 仅补 2 天内的缺口
df["is_promo"] = df.index.isin(pd.to_datetime(promo_dates)).astype(int)  # 促销标记
# 节假日标记可借助 holidays 等库，或用自建日历；这里只演示结构
df["dow"] = df.index.dayofweek            # 星期几效应是电商最关键的模式之一

03 · EDA：先建立节奏感

跑模型前先用 EDA 建立对数据的直觉。建议至少做这几件事：

  • 画原始序列图，看长期趋势与明显的周期；
  • 按周/月/年聚合，判断季节周期长度；
  • 画ACF/PACF，初步判断自相关结构；
  • 做 STL 分解，拆出趋势、季节与残差；
  • 量化促销/节假日的影响幅度。
电商数据的共同节奏：周内效应（如周末高于工作日）往往非常明显。它也是 seasonal-naive（周期取 7）常常很强的根本原因。若你的 EDA 完全看不到周内周期，先怀疑数据管道或用户群特殊，而不是直接上更复杂的模型。

04 · Baseline：先知道“不用模型”有多强

任何项目都先用两个最简模型立底：naive（预测值等于最后一个观测）与 seasonal-naive（预测值等于上一个同季节周期的观测，周周期取 7）。它们不是“随便看看”——如果复杂模型赢不了它们，就不能宣称有价值。

比较时不要只看 MAE/RMSE，推荐同时报 MASE（Mean Absolute Scaled Error），因为它用朴素预测的误差做分母，使不同序列、不同尺度可比：

1H∑t=1H|et|1T−1∑t=2T|yt−yt−1|
分母是训练集上一步朴素预测的平均绝对误差（即一阶差分绝对值的均值），仅作尺度基准。MASE < 1 意味着比一步朴素预测更好（与季节性的关系取决于分母的选择）。
import numpy as np

def naive(train, h):
    return np.full(h, train[-1])

def seasonal_naive(train, h, s=7):
    rep = int(np.ceil(h / s))
    return np.tile(train[-s:], rep)[:h]

# 评估：同时报 MAE 与 MASE（分母为训练集一步朴素误差）
def mase(y_true, y_pred, y_train):
    scale = np.mean(np.abs(np.diff(y_train)))
    return float(np.mean(np.abs(np.asarray(y_true) - y_pred)) / scale)

如果 seasonal-naive 的 MASE 已经很小（例如明显小于 1），说明数据里的周内结构很强，后续模型的提升空间主要在外部特征与非线性上，而不是在“记住周期”。

05 · 统计模型：ETS 与 SARIMA

有基线之后可以上统计模型。ETS 把误差、趋势、季节三个分量的组合参数化（见 第 5 章）；SARIMA 在 ARIMA 基础上加一层季节阶数（见 第 12 章）。用 statsmodels 可以直接拟合：

from statsmodels.tsa.holtwinters import ExponentialSmoothing
from statsmodels.tsa.statespace.sarimax import SARIMAX

ets = ExponentialSmoothing(y_train, seasonal_periods=7,
                           trend="add", seasonal="add").fit()
ets_pred = ets.forecast(len(y_test))

sarima = SARIMAX(y_train, order=(1, 1, 1),
                 seasonal_order=(1, 1, 1, 7),
                 enforce_stationarity=True,
                 enforce_invertibility=True).fit(disp=False)
sarima_pred = sarima.forecast(len(y_test))

阶数搜索不要盲目遍历。一个合理做法是：先用 AIC/BIC（见 第 4 章）在同一数据上筛出几个候选，再用时序验证（见 第 22 章）比较泛化表现——AIC 选出的模型不等同于预测最优的模型。同时检查残差是否还有自相关（Ljung-Box），否则说明季节性或趋势没建完。

06 · 机器学习：特征工程 + 梯度提升

统计模型只用目标自身的历史。要引入促销、节假日、天气等外部信息，通常要把问题转成监督学习：用过去的信息构造特征，预测未来的目标值。关键是不泄漏未来（见 第 19 章）：

def make_features(df, target="sales", lags=(1, 7, 14), windows=(7, 14, 28)):
    X = df.copy()
    X["dow"] = X.index.dayofweek
    X["month"] = X.index.month
    for lag in lags:
        X[f"lag_{lag}"] = X[target].shift(lag)          # 只用 t-lag 及更早
    for w in windows:
        X[f"roll_mean_{w}"] = X[target].shift(1).rolling(w).mean()   # shift(1) 防止把 t 包进去
    return X.dropna()

from sklearn.ensemble import GradientBoostingRegressor
model = GradientBoostingRegressor(random_state=0)
# 特征与目标需按时间切分；树模型不能外推，趋势项需单独处理（见第 20 章）

梯度提升的优点是能自动利用特征交互、对异常值相对鲁棒、训练快。但有两个时序特有的陷阱：（1）树模型无法外推趋势——如果目标带长期增长，需先去趋势或用差分；（2）滚动特征必须用 shift 严格对齐，任何把 t 当特征的做法都是泄露。

07 · 深度模型：LSTM 与 PatchTST

当数据量足够（数千个时间点以上）且特征工程已到位，可以尝试深度模型：LSTM 适合序列建模，PatchTST 把序列切成 patch 后用 Transformer 编码。用统一接口的库（如 Darts）便于快速对比：

from darts.models import RNNModel, PatchTSTModel
from darts import TimeSeries

train = TimeSeries.from_series(y_train)
lstm = RNNModel(model="LSTM", hidden_dim=64, n_rnn_layers=2,
                input_chunk_length=30, training_length=60, n_epochs=50, random_state=0)
lstm.fit(train)
lstm_pred = lstm.predict(len(y_test))

patch = PatchTSTModel(input_chunk_length=60, output_chunk_length=14,
                      patch_length=8, n_epochs=50, random_state=0)
patch.fit(train)
patch_pred = patch.predict(len(y_test))

两点必须记住：一是可比性——深度模型必须用与统计模型完全相同的时序验证划分，否则任何“更好”都不可信；二是随机性——训练需要固定随机种子并重复运行看方差，单次结果不具代表性。

08 · 集成：为什么组合常常有效

不同模型的误差结构不同：统计模型强在周期与平滑，树模型强在外部特征，深度模型强在复杂模式。把它们组合，往往能降低方差。最简的是等权平均；更系统的是 Stacking——用各基模型的预测作为特征，训练一个元模型学习组合权重。

09 · 评估对比：只比同一把尺子

不同模型族各有取舍。下表描述的是典型取舍，不是具体分数；任何优劣都必须在你的数据上用同一套时序验证测量：

模型族典型优势主要代价需注意
naive / seasonal-naive零训练、可解释、难被大幅超越无法利用外部特征应始终作为参照底线
ETS / SARIMA可解释、自带区间、适合平稳/季节序列需定阶、难融合多外部变量残差诊断与差分次数
梯度提升能利用大量外部特征与交互无法外推趋势，易受泄漏影响滞后特征严格对齐
深度模型可学习复杂模式、可多变量需大量数据、训练与调参成本高固定种子、重复运行看方差
集成 / Stacking带不同误差结构、降低方差维护成本、元模型可能过拟合元模型训练集需与评估集分离

一个常被忽略的规律：从 baseline 到统计模型往往提升最大，之后再复杂化边际收益递减。选择模型的依据应是业务需求（延迟、可解释、是否需要区间），而不是“越新越好”。

10 · 部署模拟

选定方案后，按 第 27 章的流程上线：

  1. 序列化模型（pickle / ONNX）并写入版本与训练数据窗口；
  2. 用 FastAPI 封装 /predict 接口，校验历史长度；
  3. 在 Model Registry 记录当前版本与回滚点；
  4. 部署残差监控与漂移告警；
  5. 配置定期 + 漂移触发的重训练流水线。
集成的降级：若某个基模型不可用（文件损坏、超时），集成可能产生异常输出。稳妥做法是加一层范围校验：输出超出合理范围（如销量为负）时自动回退到单个稳定模型（如 seasonal-naive 或 SARIMA）。

11 · 时序预测的常见错误

下面这些是全课程反复强调、也最常见的问题，可以当作自检清单：

#错误后果正确做法
1用随机划分代替时间划分数据泄露、评估虚高按时间顺序切分（第 22 章）
2用未来信息构造特征离线好、线上差只用 t−1 及更早的信息
3不做平稳性/单位根检查伪回归、预测不可靠先检验、必要时差分（第 3 章）
4只看 MAE/RMSE，不看残差漏掉模型可改进空间看残差自相关与诊断图
5不在同一验证上比较模型结论不可信统一时序验证划分
6对同一测试集反复调参过拟合测试集保留 holdout，只在最后用
7忽略节假日与外部事件节日期间误差巨大加入日历与事件特征
8预测长度随意设定长周期预测不可靠horizon 由业务需求决定
9认为“部署即结束”模型静默降级监控、告警与重训练（第 27 章）
10把回测分数当真实业务收益决策误判区分离线指标与上线效果

13 · 结语：三个可带走的心理模型

时间序列分析处在统计学、机器学习与领域知识的交叉点。它不像纯视觉或 NLP 那样“堆数据和算力”就能解决：做好预测，既需要统计理论的严谨，也需要对业务场景的洞察。把整门课压缩成三句话：

① 先立基线，再复杂化。seasonal-naive 与一个调好的统计模型，是任何新方法都必须先超越的底线。
② 用同一把尺子。时序验证、残差诊断与同一评估口径，比任何单一分数都重要。
③ 部署即开始。线上监控与重训练，和模型本身一样是交付物的一部分。

George Box 的话值得反复回味：“All models are wrong, but some are useful.” 目标不是找到“正确”的模型，而是找到在明确假设与限制下有用的模型。若手边还没有可实践的数据，不妨找一个公开数据集，从第 28 章的框架出发跑一遍完整流水线。
