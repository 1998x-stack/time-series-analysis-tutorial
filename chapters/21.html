CHAPTER 21 / 28 · AUTOMATED FORECASTING

Prophet 与自动预测

前两章是“手工打造”：自己造滞后、滚动、日历特征，再喂给树模型。这一章转向“自动挡”：Prophet 的加性分解，以及 Nixtla 生态中面向大规模序列的 statsforecast 与 mlforecast。

机制图解 · 原生数学排版 · 可复现模拟 · 适用边界

如果只是要一个合理的 baseline，或者在几百上千条序列上批量预测，从头设计特征并不划算。自动预测工具把经过验证的分解与建模策略封装起来，几行代码就能出结果。理解它们做了什么假设，才知道什么时候能用、什么时候会失效。

01 · 为何要自动预测

手工特征工程路线效果好、可控性强，但代价是每个新数据集都要重新设计特征、重新调参。当序列数量从几条变成几千条、当业务方只想要一个“明天大概多少”的估计时，这种投入就不划算了。自动预测工具的目标，是把“分解 + 建模 + 产生区间”这套流程封装成稳定的默认值。

本章介绍两条主线：Meta 开源的 Prophet（强调可解释的加性分解），以及 Nixtla 生态中的 statsforecast（经典统计模型的高性能实现）与 mlforecast（自动特征工程 + 任意 ML 模型）。它们不是“更准”，而是“更快拿到一个可信的 baseline”。

02 · Prophet 的加性分解

Prophet 把序列写成若干可解释分量之和。注意变化点位于趋势项内部，它并不是一个独立相加的分量：

y(t)=g(t)+s(t)+h(t)+εt
g 是带变化点的分段趋势，s 是傅里叶级数形式的季节项，h 是节假日效应，ε 是误差。当季节振幅随水平放大时，Prophet 提供乘法形式：y = g(t)·[1 + s(t) + h(t)] + ε。

这种“分而治之”的好处是每个分量都能单独解释与单独控制，坏处是它假定各分量相加独立，无法表达“季节性振幅随趋势变化”这类交互（除非改用乘法形式）。

03 · 组件与关键参数

趋势 g(t)。默认为分段线性：先给一组潜在变化点（默认为前 80% 历史均匀放置若干点），每个点处允许斜率改变。也可选逻辑增长曲线，用于有饱和上限的场景（如市场渗透率）。changepoint_prior_scale 控制斜率变化的幅度：默认 0.05，越小趋势越僵、越大越易贴住波动而过拟合。

季节性 s(t)。用傅里叶级数表示，add_seasonality 可以为任意周期添加自定义季节项，因此“每两周一次”这类次周期也可以建模，只是默认不自动开启。默认年周期阶数 10、周周期 3、日周期 4；阶数越高越灵活也越易过拟合。

节假日 h(t)。传入节假日表（含名称与日期），Prophet 会为每个节假日及其 lower_window / upper_window 天数生成指示特征，从而学习“节前/节后”的效应。

外生变量。通过 add_regressor 引入额外回归量；但未来期的回归量取值必须你自己提供，否则无法预测——这与上一章“特征必须可得”是同一个约束。

不确定区间。默认通过对趋势不确定性的模型假设做蒙特卡罗采样得到，可选 full Bayesian sampling（基于 Stan）。区间的可信度取决于假设本身，在数据稀少时不应过度信任。

04 · 优势与局限

方面优势局限
上手成本默认值可用，无需特征工程默认值不一定适合每条序列
分量解释趋势/季节/节假日可单独可视化加法假设限制了分量间的交互
缺失与异常对缺失与局部异常较宽容宽容不等于正确处理，重大突变需标注
外生变量支持 add_regressor未来回归量必须可得；多变量效果不如树模型
季节性傅里叶项可调，支持自定义周期高频、短周期模式需手动配置
规模小规模快、结果稳定上万条序列时逐条拟合很慢（官方亦推荐分批/并行）

一句话：Prophet 适合中低频、趋势与季节结构清晰、需要向业务方解释的场景；它不适合高频交易、强交互效应或需要大量外生变量的任务。

05 · Nixtla 生态：面向多序列的工具链

当序列数量上千、甚至百万时，逐条跑重模型的代价难以接受。Nixtla 生态把三类需求分开：

  • statsforecast：用 numba 加速的经典统计模型实现，提供统一的 AutoARIMA、AutoETS、AutoTheta、TBATS、MSTL 等接口，并原生支持多条序列并行。官方文档声称在大规模上相对传统实现有显著提速（具体倍数随数据与硬件而变）。
  • mlforecast：把第 19 章的滑窗特征工程自动化——你只需声明 lags、lag_transforms（如滚动均值）、date_features 与 target_transforms（如差分），它自动生成特征并保证不引入未来信息，再交给任意 ML 模型（LightGBM、XGBoost 等）。
  • neuralforecast：把 RNN、TCN、Transformer 等神经网络模型封装成同一套 API，对应后面几章的内容。

需要区分的是：statsforecast 解决“快”，mlforecast 解决“自动化特征工程”，它们都不会替你判断哪些特征、哪种假设适合你的数据。把它们当作加速器，而不是替代思考的黑箱。

依赖提示：Prophet、statsforecast、mlforecast 都不在本书示例的依赖清单（numpy / statsmodels / scipy）内，需自行安装后使用。本章的可运行实验只用 numpy 实现同样的“加性分解”思想。

07 · Python 实验：用最小二乘复现加性分解

Prophet 的趋势与傅里叶季节项，在给定变化点后本质上是一个线性模型。下面用 numpy 的最小二乘拟合“线性趋势 + 周周期傅里叶项”，看各分量被如何估计。只依赖 numpy。

import numpy as np
rng = np.random.default_rng(2100)
n = 140
t = np.arange(n)
y = 0.4 * t + 3 * np.sin(2 * np.pi * t / 7) + 1.2 * np.cos(2 * np.pi * t / 7) + rng.standard_normal(n)

X = np.column_stack([np.ones(n), t, np.sin(2 * np.pi * t / 7), np.cos(2 * np.pi * t / 7)])
w = np.linalg.lstsq(X, y, rcond=None)[0]
r2 = lambda obs, pred: 1 - ((obs - pred) ** 2).sum() / ((obs - obs.mean()) ** 2).sum()

print("系数 [常数, 趋势, sin, cos] =", np.round(w, 3))   # ≈ [0.128 0.399 3.107 1.201]
print("R2 =", round(r2(y, X @ w), 4))                    # ≈ 0.9965
assert abs(w[2] - 3) < 0.5 and abs(w[3] - 1.2) < 0.5    # 季节系数接近真值

预期结果：趋势斜率约 0.40、sin/cos 系数约 3.11 与 1.20，与生成时的真值接近，R² 约 0.9965。这是合成数据上的机制验证，说明“给定变化点的分解 = 线性最小二乘”，不代表 Prophet 在其他数据上的表现；Prophet 额外做了变化点自动选择、加权拟合与区间估计。

08 · 小结

Prophet 把预测拆成趋势（含变化点）、傅里叶季节性、节假日与误差，胜在可解释与上手快；Nixtla 生态的 statsforecast 与 mlforecast 则面向“大量序列 + 自动特征工程”。它们共同的边界是：都依赖你要先把时间对齐、泄露排除、验证做对。

选择自动工具前请先回答：序列数量与频率是多少？需要外生变量吗（未来取值可得吗）？季节振幅是否随水平变化（要不要乘法形式）？预测区间将如何被使用？最后，用什么时序交叉验证来证明它比简单基线更好？
